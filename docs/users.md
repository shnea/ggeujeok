# 사용자 기능 기준

로그인·댓글·좋아요·내 활동·알림의 기준 문서다. 별도 표시가 없는 정책은 **확정**이다. 글 열람 상태는 [콘텐츠 기준](content.md#posts), 외부 인증 계약은 [플랫폼 자료](platform-integration.md)를 따른다.

<a id="auth"></a>
## 인증·관리자·세션

- **사용자 확정:** 로그인 화면은 끄적과 이용 기능을 안내한다. 버튼·일반 안내에는 내부 연동 명칭인 `플랫폼 계정`을 노출하지 않는다. 블로그의 주제·성격은 임의로 정하지 않는다.
- 관리자와 일반 사용자는 공통 OIDC를 사용한다. 검증한 `iss`+`sub`를 내부 User와 유일하게 연결하고 이메일만으로 환경 간 계정을 합치지 않는다. 비밀번호는 끄적에 저장하지 않는다.
- 작성자 한 명을 정확한 `iss/sub`로 지정한다. 이메일·최초 로그인으로 자동 승격하지 않는다.
- NestJS가 콜백·세션·업무 권한을 소유하고 PostgreSQL에 세션을 저장한다. 인증 성공 시 세션 ID를 교체한다.
- **사용자 확정:** 기본 닉네임은 플랫폼 로그인에서 설정한 `given_name`을 사용한다. 기본값은 로그인마다 동기화한다. `/me/settings`에서 끄적 전용 닉네임을 설정할 수 있으며 설정한 이름은 재로그인해도 유지한다. `기본 닉네임 사용`으로 최신 로그인에서 받은 이름으로 돌아갈 수 있다. 표시 이름 변경은 기존 댓글·멘션·알림에도 반영한다. 기존 캐시는 다음 로그인까지 유지한다. 검증한 ID token에 없으면 동일 subject의 UserInfo에서 확인하고, 없으면 플랫폼에서 설정 후 재로그인하도록 안내한다. `name`·이메일·생성 ID를 닉네임으로 대신 공개하지 않는다. 회원 댓글에는 비밀번호·보안문자 입력을 표시하지 않는다.
- 브라우저는 같은 출처 HttpOnly 쿠키를 사용한다. HTTPS 개발·운영 모두 Secure·SameSite=Lax, 변경 요청은 CSRF 검증을 적용한다. 유휴 24시간 또는 생성 후 최대 7일에 만료한다.
- 호스트 로그아웃 시 서버 세션을 폐기하고 OIDC 로그아웃도 설계한다. 허용된 복귀 URL·즉시 계정 중지 요구는 실제 플랫폼 설정과 대조한다. JWT 자체 검증만으로 즉시 폐기를 보장하지 않는다.
- OIDC 라이브러리의 state·nonce·PKCE·서명·issuer·만료·토큰 종류별 audience 검증을 사용한다. 디코딩만으로 인증하지 않으며 ID token을 업무 API 토큰으로 사용하지 않는다.
- 일반 사용자 API는 세션과 소유권, 관리자 API는 지정 관리자 여부를 서버에서 검사한다. 공개 API와 분리하고 프런트의 숨김 처리만으로 권한을 통제하지 않는다.
- 좋아요와 회원 댓글은 로그인을 사용하고 원문 댓글 영역으로 복귀한다. 비회원은 아래 별도 작성 절차를 사용할 수 있다. 취소·동의 거부·만료·재로그인 때 작성 중 내용을 보호한다.
- 플랫폼 키, [자동화 전용 토큰](content.md#automation), 사용자 세션은 별개다. 서버 키를 브라우저·URL·로그에 넣지 않는다.

## 댓글·좋아요·내 활동

### 내 설정

- 끄적 전용 닉네임은 2~30자로 문자·숫자·공백·밑줄·마침표·하이픈을 허용하며 앞뒤 공백 제거·NFC 정규화를 적용한다. 일반 회원의 직접 설정에는 `관리자`·`운영자`를 허용하지 않는다. 중복은 허용하며 계정·댓글 소유권과 무관하다.
- `GET/PUT /api/me/profile`은 로그인한 본인만 조회·변경하며 PUT은 CSRF를 검증한다. `nickname: null`은 전용 이름만 지우고 기본값을 사용한다. 기본 이름과 전용 이름을 따로 보관해 동시 로그인·변경 때 덮어쓰지 않는다.

### 댓글

- 회원·비회원은 공개 글에 평문 1~2,000자 댓글을 작성한다. 회원은 본인 댓글만 수정·삭제하고 관리자는 모든 댓글을 삭제할 수 있다. 관리자가 타인의 문장을 수정하지는 않는다.
- 회원 표시 이름은 [인증 정책](#auth)에 따라 끄적 전용 닉네임이 있으면 우선 사용하고, 없으면 계정 닉네임을 사용한다. 플랫폼과 동일하게 닉네임 중복을 허용하며 소유권은 내부 사용자 ID로 구분한다. 댓글에 회원/비회원/글 작성자 구분을 표시한다.
- **사용자 확정:** 비회원은 닉네임·수정/삭제용 비밀번호·자체 이미지 보안문자로 작성한다. 이메일을 받지 않으며 비회원에게 앱 내 알림을 제공하지 않는다. 비회원 닉네임 중복은 허용하되 비회원 표시는 항상 붙인다. `관리자`·`운영자` 닉네임은 비회원이 사용할 수 없다. 비회원 닉네임은 2~30자로 문자·숫자·공백·밑줄·마침표·하이픈을 허용한다.
- 비회원 비밀번호는 8~128자이며 무작위 salt를 사용한 scrypt 해시만 보관한다. 수정·삭제 때 비밀번호와 새 보안문자를 모두 확인한다. 비밀번호 복구 기능은 없으며 관리자 삭제는 가능하다.
- 보안문자는 숫자 6자리 PNG이며 5분·1회 유효하다. 정답은 클라이언트에 보내지 않고 검증값만 저장한다. 새 발급 시 이전 이미지를 무효화하고 잘못된 정답·비밀번호에도 같은 문자를 재사용하지 못한다. 쿠키에 연결된 검증과 같은 출처 검사를 수행한다. 읽기 어려우면 재발급하거나 회원 로그인을 사용할 수 있다.
- HTML을 실행하지 않는다. 작성은 사용자당 분당 5회·시간당 60회로 제한하고 초과 시 429와 재시도 정보를 반환한다. IP 전체를 한 사용자로 취급하지 않는다.
- 비회원 작성은 임시 브라우저 식별자당 같은 5회/60회 제한, 보안문자 발급은 분당 20회·시간당 100회다. 비회원 식별 쿠키는 Secure·HttpOnly·SameSite=Lax로 24시간 유효하며 원문 대신 해시로 연결한다. 활동 시각은 제한된 배열로 보관하고 하루 동안 활동이 없는 비회원 기록은 다음 발급 때 정리한다. 429에는 `Retry-After`와 `retryAfterSeconds`를 제공한다.
- **사용자 확정:** 대댓글은 한 단계로 들여쓴다. 대댓글에 답글을 달면 원댓글 아래 같은 깊이에 배치하되 `@대상 닉네임`을 표시한다. 대상 댓글 ID로 연결하며 회원 닉네임 변경도 표시 이름에 반영한다. 대상 댓글 삭제 후에는 `@삭제된 댓글`로 표시한다.
- Comment는 id, post_id, parent_id(원댓글), reply_to_id(실제 답글 대상), 회원 user_id 또는 비회원 닉네임/비밀번호 해시, content, status, created_at, updated_at을 관리한다. 다른 글·다른 원댓글 묶음의 대상을 지정하거나 두 단계 부모를 만드는 요청을 거부한다. 작성 요청 ID와 입력 해시로 응답 유실 재시도의 중복 등록을 막으며 같은 ID의 다른 입력·대상은 거부한다.
- 삭제 시 본문·작성자 연결·비회원 이름/비밀번호 해시·요청 해시를 제거한다. 답글 연결에 필요한 식별자·시간·삭제 상태는 남기고, 답글이 있는 원댓글만 `삭제된 댓글입니다.`로 노출한다. 마지막 답글도 삭제되면 빈 묶음은 목록에서 숨긴다. 삭제된 원댓글에는 직접 답글을 달 수 없지만 남아 있는 대댓글에는 답글을 달 수 있다. 게시글 삭제 시 댓글과 답글을 함께 제거한다.
- 공개 댓글은 원댓글 묶음 20개씩, 답글은 해당 묶음을 펼쳐 20개씩 조회한다. 댓글 수는 삭제되지 않은 원댓글과 답글의 합계이며, 원댓글 페이지 수와 구분한다.
- 입력 내용과 요청 ID는 해당 탭의 sessionStorage에 임시 보관하고 등록 성공 때 제거한다. 회원 입력은 작성 계정과 연결하며 다른 계정으로 자동 복원하지 않는다. 비회원 비밀번호와 보안문자는 임시 보관하지 않는다. 보관 실패는 복사 안내를 제공한다.
- 댓글은 작성일·ID 오름차순으로 20개씩 조회한다. 관리 화면 `/admin/comments`에서는 공개/비공개 글을 포함해 최신 댓글을 20개씩 조회·삭제한다. 관리자 타인 댓글 삭제는 감사 이벤트에 남긴다. 공개 글을 비공개로 바꾸면 일반 댓글 조회·쓰기·비회원 수정/삭제를 모두 차단한다.
- 댓글 삭제 시 [알림](#notifications)과 내 활동에 반영한다. 비공개 글을 일반 사용자의 댓글 목록으로 우회 노출하지 않는다.
- 사용자 확정: 게시글마다 `댓글 허용`을 설정한다. 기존 글·새 글의 초기값은 허용이다. 편집본에 자동 저장하고 공개본 반영 시 적용한다. 끄면 회원·비회원·관리자의 새 댓글과 답글을 서버에서 차단하며, 기존 댓글 읽기·권한에 따른 수정/삭제·좋아요는 유지한다. 작성 트랜잭션이 게시글 행을 공유 잠금으로 읽어 공개본 변경과 직렬화한다.

구현 API: 공개 조회 `/api/public/posts/{slug}/interactions?page=1`, 답글 조회 `/api/public/posts/{slug}/comments/{원댓글Id}/replies?page=1`, 회원 작성/수정/삭제 `/api/posts/{postId}/comments[/{id}]`, 관리자 목록 `/api/admin/comments?page=1`. 답글 작성은 기존 작성 API에 `parentId`·`replyToId`를 추가한다. 비회원은 `/api/guest/captcha` 발급 후 `/api/guest/posts/{postId}/comments[/{id}]`에 보안문자 식별자·입력값·비밀번호를 전달한다. 회원 변경 API는 세션·CSRF를 검사한다.

### 좋아요

- 로그인 사용자는 공개 글에 한 번 좋아요를 등록하고 다시 누르면 취소한다. UI는 토글, API는 등록·취소 각각 멱등 처리한다.
- PostLike는 id, post_id, user_id, created_at을 두고 `post_id+user_id` 유일성을 DB에서 보장한다.
- 좋아요 변경은 사용자당 분당 60회다. 중복·재시도·동시 요청에도 개수와 상태가 맞아야 한다.
- 구현 API는 `/api/posts/{postId}/like`의 PUT(등록)·DELETE(취소)이며 본인의 상태와 합계만 반환한다. 이미 같은 상태인 요청은 빈도 한도를 추가로 소비하지 않는다. 비회원 좋아요는 제공하지 않는다.

### 내 활동

- 경로: `/me`, `/me/comments`, `/me/likes`, `/me/notifications`.
- 댓글 목록: 글 제목·댓글 일부·작성/수정일·원문 이동·수정·삭제.
- 좋아요 목록: 대표 이미지·글 제목·요약·좋아요 시점·원문 이동.
- 댓글·내 활동·알림은 페이지당 20개, API 최대 50개이며 동률에도 안정적으로 정렬한다.
- 구현 API는 `/api/me/comments?page=1`, `/api/me/likes?page=1`이며 세션의 본인 기록만 반환한다. 현재 공개 글만 표시하고 관리자에게는 비공개 글의 본인 활동도 허용한다. 수정·삭제·좋아요 취소는 기존 권한 API를 사용한다.
- 댓글 원문 링크는 현재 글 공개 여부와 댓글 상태를 확인한 뒤 원댓글 페이지·답글 페이지를 계산해 이동한다. `/api/public/posts/{slug}/comments/{id}/location`은 공개 상태의 댓글만 반환한다. 관리자 비공개 알림은 `/admin/comments?comment={id}`로 해당 댓글만 확인한다.

## 최소 앱 내 알림

사용자는 플랫폼의 알림 API 미제공에 대해 **끄적 내부 최소 구현을 예외로 허용**했다. 일반 알림 플랫폼이나 교체용 범용 추상화는 만들지 않는다.

- 공개 글에 새 댓글이 생기면 글 작성자에게 알림을 생성한다. **구현 선택:** 답글은 실제 답글 대상 댓글의 회원 작성자에게도 보낸다. 동일 수신자는 한 번만 알리며 답글 유형을 우선한다. 자기 댓글은 자신에게 알리지 않는다.
- 비회원 댓글·답글도 위 조건으로 회원에게 알린다. 비회원 자신은 수신 계정이 없으므로 알림을 받지 않는다. 도입 이전 댓글에는 과거 알림을 일괄 생성하지 않는다.
- 댓글과 수신자별 처리 기록을 같은 DB 트랜잭션으로 저장하고 별도 워커가 알림을 생성한다. 생성과 처리 완료 표시를 같은 트랜잭션에 둔다. API 이미지의 `worker.js`를 재사용하며 별도 큐 서버를 두지 않는다.
- 댓글 이벤트 ID·수신자 유일성으로 중복 알림을 막는다. 워커는 2초 간격으로 최대 25건씩 처리하며 최대 5회 시도하고 지수 간격으로 재시도한다. 실패 코드와 시도 횟수를 DB와 구조화된 컨테이너 로그에 남긴다. 공통 플랫폼 로그 연결은 후속 작업이다. 전달 실패는 댓글 저장 결과를 취소하지 않는다.
- Notification은 수신자, 이벤트 ID, 글/댓글 참조, 유형, 생성일, 읽은 시각을 관리한다.
- 기능: 본인 목록·알림 내용·생성일·읽음 여부, 개별/전체 읽음, 읽지 않은 개수, 글·댓글 위치 이동.
- 전체 읽음은 요청 시점까지 도착한 알림만 대상으로 해 동시에 들어온 새 알림을 읽음으로 잃지 않게 한다. 이동 시 현재 대상 열람 권한을 다시 검사한다.
- 읽음과 무관하게 생성 후 90일 보존하며 목록·개수에서도 만료 항목을 제외한다. 완료된 처리 기록은 90일 뒤 정리하고 실패·미완료 기록은 임의로 지우지 않는다. 댓글 삭제 시 대기 기록과 연결 알림을 함께 제거한다. 글 비공개 시 일반 사용자의 목록·개수·이동에서 숨기고 관리자 수신자는 관리 권한으로 확인한다.
- 화면 진입·사용자 새로고침·읽음 처리 후 개수를 갱신한다. WebSocket·SSE·외부 푸시를 추가하지 않는다.
- 구현 경로는 GET `/api/me/notifications?page=1`, GET `/api/me/notifications/unread-count`, POST `/api/me/notifications/{id}/read`, POST `/api/me/notifications/read-all`, GET `/api/me/notifications/{id}/destination`이다. 변경은 CSRF·본인 권한을 검사한다. 읽음은 멱등이며 전체 읽음은 단일 SQL의 시작 스냅샷을 기준으로 한다.
- 보존 정리는 [운영 작업](operations.md#observability)에서 수행한다. 이메일·SMS·카카오·Telegram·Web Push는 사용하지 않는다.

## 수용 조건

- 로그인 성공·취소·만료·다른 환경 토큰 거부·로그아웃·재로그인을 실제 DEV에서 검증한다. Mock만으로 실제 제공자 검수를 대체하지 않는다.
- 일반 사용자의 관리자 접근, 타인 댓글 수정/삭제, 타인 활동·알림 조회/읽음, 비공개 글 접근을 거부한다.
- 댓글·좋아요의 입력·빈도·동시 요청·재시도·집계와 내 활동의 링크·수정·삭제를 확인한다.
- 알림 중복·실패 후 재처리·댓글 삭제·전체 읽음 중 신규 도착·보존 만료·비공개 전환을 확인한다.
- PC·모바일·키보드로 로그인·댓글·좋아요·내 활동·알림 흐름을 사용할 수 있어야 한다.
