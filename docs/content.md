# 콘텐츠 기능 기준

이 문서는 글·파일·자동화·공개 화면의 상세 요구사항을 관리한다. 별도 표시가 없는 정책은 사용자 결정 또는 추천안 위임으로 **확정**됐다. 공통 인증은 [사용자 기준](users.md#auth), 통계·배포는 [운영 기준](operations.md), 외부 계약은 [플랫폼 자료](platform-integration.md)를 참조한다.

## 게시글·분류

### 관리와 상태

- 작성자는 한 명이다. 관리자만 글 작성·수정·삭제·공개/비공개·분류 관리·미리보기를 사용할 수 있다. 모바일에서도 최소한의 관리가 가능해야 한다.
- 글 상태는 `DRAFT`, `PUBLIC`, `PRIVATE`다. 공개에는 비어 있지 않은 본문과 카테고리 한 개가 필요하다. 초안에는 카테고리 미지정을 허용한다.
- 글 정보는 제목·본문·대표 이미지·요약·상태·카테고리·태그·작성자·작성일·수정일·공개일이다.
- 제목 1~200자, 요약 최대 500자, version 3 본문 JSON 최대 2MiB, 태그 최대 20개다.
- 최초 공개일을 보존하고 재공개·수정으로 최신 목록 맨 위에 올리지 않는다. 공개 전 slug는 소문자 영문·숫자·하이픈 1~120자이며 중복이면 수정을 요청한다. 최초 공개 후에는 변경할 수 없다.
- 비공개·삭제 글은 공개 API·검색·피드·관련 글·일반 사용자의 활동 목록에서 제외한다. 관리자는 별도 권한으로 확인한다. 숨긴 글의 제목·파일 존재 여부도 불필요하게 노출하지 않는다.
- 삭제는 관리자 확인 후 글과 종속 댓글·좋아요·알림·편집본을 제거한다. 진행 중 요약은 대상 존재·변경 번호 검사로 반영하지 않는다. 파일 원본은 즉시 삭제하지 않고 [파일 정리 정책](#media)을 따른다.

### 자동 저장

- 마지막 변경 후 3초 또는 편집 지속 중 최대 30초 간격으로 저장한다. 요청이 겹쳐 저장 순서가 뒤집히지 않게 한다.
- 게시글당 `PostDraft` 한 개에 편집 중 전체 스냅샷·변경 번호·기반 게시글 번호를 둔다. 공개 글의 자동 저장은 공개본에 즉시 반영하지 않는다.
- 명시적 반영 시 기반 번호를 확인하고 Post를 원자적으로 갱신한다. 다중 탭·자동화 수정 충돌은 409로 알리고 자동 덮어쓰지 않는다.
- 저장 중·성공·실패·충돌을 구분하고 화면 이동 시 미저장 변경을 안내한다. 본문 교체·늦은 조회 응답이 새 편집을 덮어쓰지 않게 한다.
- 전체 수정 이력과 휴지통은 만들지 않는다.

### 카테고리·태그

- 카테고리는 추가·수정·삭제·정렬을 지원한다. 글 하나의 기본 카테고리는 한 개이며 복수 분류는 태그로 처리한다.
- 사용 중인 카테고리는 글을 다른 카테고리로 옮기기 전 삭제할 수 없다.
- 관리자 카테고리 화면은 이름(1~80자), 분류 주소, 표시 순서(0~10000, 작은 수 우선)를 관리한다. 이름은 공백 제거·NFC·대소문자 정규화로, 주소는 고유 값으로 중복을 막는다. 주소를 변경하면 기존 분류 링크가 달라진다.
- 사용 여부에는 공개·비공개 글과 편집본을 모두 포함하고, 같은 글의 공개본/편집본은 사용 글 수에서 한 번만 센다. 편집본 JSON에서 생성한 DB 외래 키로 동시 저장·삭제 때도 참조를 보호한다. 사용 중인 분류를 바꾸려면 편집본 저장과 공개/비공개 반영까지 완료해야 한다.
- 태그 입력은 Enter 확정·Chip 표시·제거·기존 태그 자동완성을 지원한다. 태그별 글을 조회할 수 있어야 한다.
- 관리자 검색은 `/api/admin/tags?q=검색어`를 사용한다. 저장된 편집본과 기존 태그 목록을 함께 검색하고, 동일한 정규화 이름은 기존 목록의 표시 이름을 우선한다. 공개/비공개 반영으로 등록된 태그는 글에서 제거한 뒤에도 재사용 후보로 남으며, 편집본에만 있던 태그는 해당 편집본에서 제거되면 사라진다. 이 후보 목록은 공개 API로 제공하지 않는다.
- 검색어는 최대 80자이며 완전 일치 → 앞부분 일치 → 포함 순으로 최대 8개를 제안한다. 현재 글에 추가한 태그는 화면 후보에서 제외한다. 방향키·Enter·마우스/터치 선택을 지원하고 새 이름은 Enter 또는 추가 버튼으로 확정한다. 한글 조합 중 Enter는 태그를 확정하지 않는다. 입력 후 200ms에 검색하며 이전 요청은 취소한다. 검색 실패 시 재검색 또는 직접 추가를 허용한다.
- 표시 이름은 보존하고 앞뒤 공백 제거·유니코드 NFC·대소문자 정규화 키로 중복을 막는다. 태그 삭제는 연결을 제거하며 글은 삭제하지 않는다.

### 데이터·API 경계

아래는 설계 대상이며 현재 구현된 스키마·경로가 아니다.

| 데이터 | 기준 |
| --- | --- |
| Post | id, 고유 slug, title, content JSON, summary와 출처·대상 본문 번호, thumbnail 파일 참조, status, category_id, author_id, published_at, created_at, updated_at, 변경 번호, ai_generated |
| PostDraft | 게시글당 한 개, 편집 스냅샷·자체 변경 번호·기반 Post 번호 |
| Category | id, name, 고유 slug, sort_order, created_at, updated_at |
| Tag / PostTag | 태그 id/name/slug/정규화 키/created_at, post_id+tag_id 유일성 |

관리자 진입점은 `/api/admin/*`, 공개 조회는 `/api/public/*`다. 요청 검증·권한·공개 상태 규칙은 백엔드에서 일관되게 적용한다. API 세부 요청/응답 명세는 실제 구현과 함께 관리한다.

## Editor·첨부·대표 이미지

### 본문 계약

- 공통 Editor/Viewer를 재사용하고 version 3 JSON을 검증해 저장·재조회·재편집한다. 자체 Viewer를 재구현하지 않는다.
- 패키지 설치·첨부 어댑터·상태 응답의 원본 계약은 [플랫폼 자료](platform-integration.md)에서 필요한 문서만 확인한다.
- 다른 글로 이동하면 `documentKey`를 변경한다. 화면 해제 시 이벤트·업로드 요청을 정리하되 완료 파일을 자동 삭제하지 않는다.
- 에디터 자체 보관을 영속 저장으로 간주하지 않는다. Markdown 붙여넣기·표·굵게·기울임·한글·코드·첨부가 저장과 조회 후 유지돼야 한다.
- 임의 HTML은 실행하지 않는다. 출력의 이스케이프·필요한 sanitizing을 적용하고 JSON만 받는다는 이유로 XSS 검증을 생략하지 않는다.

### 파일 접근과 업로드

- 파일 원본은 플랫폼에서 PRIVATE·영구 보존으로 관리한다. 실제 `영구` 코드 활성 여부를 연결 시 확인한다. `default`를 영구 보존으로 간주하지 않는다.
- 본문·대표 이미지에는 file ID와 필요한 참조를 저장하고 임시 URL은 저장하지 않는다. 파일의 환경·업로더·글/편집본 참조를 끄적에서 관리한다.
- 끄적의 파일 보기 API가 현재 글 공개 여부·관리자 권한·소유 관계를 확인한 뒤 서버 키로 플랫폼 `POST /api/v1/files/{id}/view-ticket`을 호출한다. `fileId`, 에디터 `scope`만으로 권한을 인정하지 않는다.
- 공개 글의 이미지는 익명 방문자와 공유 이미지 수집기가 접근할 수 있어야 한다. 보기 응답은 `no-store`이며 플랫폼 성공 JSON의 URL·임시 토큰·만료·null·추가 필드를 변경 없이 반환한다. 서버 API 키는 브라우저에 노출하지 않는다. 티켓 URL은 본문이나 로그에 저장하지 않는다.
- 중계는 등록된 환경·파일과 알려진 플랫폼 HTTPS 콘텐츠/리다이렉트 경로만 허용한다. 임의 URL을 받는 프록시는 만들지 않으며 파일 전체를 메모리에 올리지 않고 스트리밍한다.
- 이미지 파일당 20MiB, 기타 첨부 50MiB를 상한으로 한다. 실제 형식·크기를 검증하며 확장자·신고 MIME만 신뢰하지 않는다.
- 이미지 표시는 JPEG·PNG·WebP·GIF를 지원한다. SVG·HTML 등 실행 가능한 형식은 본문에 직접 표시하지 않는다. 일반 첨부는 안전한 다운로드로 제공한다.
- 생성·순차 조각 전송·완료·중단/재개·취소는 플랫폼 계약을 따른다. 끄적이 임시 원본과 재개 기록을 보관한다. 같은 요청의 재시도로 중복 파일을 만들지 않는다.
- 준비 중·완료·실패·미지원 상태와 URL 만료를 처리한다. 업로드 완료가 변환 완료를 뜻하지 않는다. 필요한 상태만 조회하고 화면을 떠나면 중단한다.
- 다른 도메인의 기본 뷰어 iframe·직접 HLS에는 제한이 있다. 본문 내 영상/오디오 플레이어와 문서 iframe 미리보기는 후속이다.

현재 이미지 업로드는 위 형식·용량 범위에서 지원하며 과도한 디코딩 자원 사용을 막기 위해 4천만 픽셀을 상한으로 둔다. 편집·읽기 공통 어댑터에 `platformImageOrigin: 'https://platform.shnea.kr'`을 설정해 에디터가 플랫폼의 이미지를 직접 표시한다. 본문은 PC(601px 이상)에서 preview, 모바일(600px 이하)에서 thumbnail을 사용하고, 클릭 확대는 모두 preview, 원본 보기는 original을 사용한다. 화면 폭에 따른 선택과 만료 갱신은 공통 에디터가 담당하며 끄적에서 기기별 분기나 URL 재조립을 하지 않는다. 상세 동작·준비 중 처리는 [공식 계약](https://platform.shnea.kr/integrations/editor.md)을 따른다. 기존 콘텐츠 중계 경로는 유지하며 영상·문서 중계 방식은 변경하지 않는다. CSP를 도입하면 `img-src`에 플랫폼 원점을 허용한다.

일반 첨부·자동 정리는 후속 구현 대상이다. 미완료 업로드는 재선택/재시도로 이어서 전송하며, 현재 임시 원본은 Docker `uploads` 볼륨에 남는다.

### 대표 이미지와 정리

- 직접 지정한 대표 이미지가 없으면 본문의 첫 이미지를 사용한다. 본문에도 이미지가 없으면 이미지 영역을 생략하고 `og:image`만 사이트 기본 이미지로 대체한다.
- 글 설정에서 본문 이미지를 선택하거나 기존 업로드 어댑터로 별도 이미지를 올린다. 자동 선택으로 되돌릴 수 있다. 대표 이미지에는 파일 ID만 저장하고 편집본 자동 저장과 공개 반영을 분리한다. 업로드 중에는 공개 반영을 막고 실패·중단 후 같은 요청으로 재시도한다.
- 대표 이미지도 해당 글·작성자·플랫폼 환경의 소유 검증과 편집본/공개본 참조 관리에 포함한다. 대표 이미지만 있고 본문이 비어 있으면 공개할 수 없다.
- 목록은 대표 이미지가 있을 때만 이미지 영역을 표시한다. 상세 화면은 본문에 없는 별도 대표 이미지만 상단에 추가해 같은 이미지를 중복 표시하지 않는다.
- 공유 metadata와 JSON-LD는 만료 토큰 대신 `/api/public/posts/{slug}/image`를 사용한다. 이 주소는 공개본의 대표 이미지를 선택하고 익명 파일 접근 권한을 재확인한 뒤 preview를 중계한다. 비공개·삭제·대표 이미지 없음은 404다. 본문 이미지 블록의 플랫폼 직접 표시 계약은 유지한다.
- 이미지가 없는 글의 공유 기본 자산은 `apps/web/public/default-og.png`, 편집 원본은 `apps/web/artwork/default-og.svg`다. 기존 끄적 워드마크·Noto Serif KR로 제작했으며 임의 소개 문구를 추가하지 않았다.
- 다른 공개 글에서 참조하는 파일은 공개 자산이다. 비공개 전용 자산과 혼용하지 않도록 관리한다.
- 블록 제거·글 저장 실패로 원본을 즉시 삭제하지 않는다. 본문·대표 이미지·편집본·진행 중 업로드를 모두 검사하고 미참조 7일 경과 파일만 삭제 직전 재검사해 정리한다.
- 플랫폼 업로드 만료와 호스트 원본·재개 기록 정리를 함께 처리한다. 키 교체 시 생성 키에 묶인 진행 업로드도 고려한다.
- 비공개 전환 후 새 티켓 발급과 기존 중계의 신규 접근을 차단한다. 이미 발급한 플랫폼 티켓은 플랫폼의 권한·만료 정책을 따르며, 다운로드한 사본·외부 공유 캐시 회수는 보장하지 않는다. 파일 원본 백업은 [운영 기준](operations.md#deployment)을 따른다.

## n8n·AI 요약

n8n은 아직 구축되지 않았다. 기존 서비스를 연결하는 것으로 가정하지 않고, 구현 5단계에서 워크플로·인증·중복 방지·요약 응답을 함께 구축하고 검증한다. 실제 연결 주소와 비밀값은 준비되기 전까지 비워 둔다.

기존 태그 자동완성은 끄적 DB 검색으로 처리하며 n8n을 호출하지 않는다. 본문 기반 AI 태그 추천은 별도 제안이며 적용 방식은 미정이다. AI 요약은 아래 확정 정책에 따라 n8n 단계에서 구현한다.

### 외부 자동화의 끄적 접근

- AI Agent/외부 자동화는 n8n을 통해 글 생성·수정·조회·상태 변경, 카테고리/태그 조회·태그 생성, 첨부 연결을 수행한다. MCP 서버는 만들지 않는다.
- 설계 진입점은 `/api/automation/*`다. 전용 토큰의 해시·권한·폐기 상태를 서버에 저장하고 원문은 비밀값 저장소에만 전달한다.
- 조회·초안 작성·공개 권한을 분리한다. 기본은 조회·초안 작성이며 PUBLIC 생성/전환은 명시적으로 허용한 토큰만 가능하다. 플랫폼 키나 관리자 세션을 재사용하지 않는다.
- 생성·업로드에 고유 요청 ID를 사용한다. 같은 ID·입력은 기존 결과, 같은 ID·다른 입력은 409다. 중복 기록은 30일 보존하며 그 이후에는 업무 대상 ID도 확인한다.
- 관리자와 자동화의 글 저장 업무는 같은 서비스를 사용한다. DEV/PROD 환경·키·파일은 섞지 않는다.
- AI 생성 글은 명시적 `ai_generated` 값으로 표시한다. n8n 등록이라는 이유만으로 AI 생성이라 추정하지 않는다.

### 요약 정책과 흐름

- 요약은 수동 요약 → 현재 본문 번호의 AI 요약 → 안전하게 추출한 본문 평문 앞 160자 순서로 표시한다. AI 요약은 자동 생성 여부를 구분할 수 있게 표시한다.
- 최초 공개·공개 본문 변경 시 수동 요약이 없을 때 요청한다. 초안 자동 저장마다 호출하지 않는다. 기존 수동 요약이 오래돼도 자동 덮어쓰지 않고 검토를 안내한다.
- 글 저장과 전달 기록을 같은 DB 트랜잭션으로 확정한 뒤 응답한다. 플랫폼 접수 장애·응답 유실은 같은 requestId·입력으로 복구한다.
- 플랫폼 Job은 큐·상태를 맡고 끄적 워커가 실제 n8n 호출을 맡는다. payload에는 글 ID·본문 번호 등 최소 식별자만 넣으며 본문·비밀값은 싣지 않는다.
- 워커는 Job을 점유하고 대상·본문 번호·기존 완료를 확인한다. 실행 중 20초마다 점유를 갱신한다. 상실·확인 실패 시 대기와 후속 변경·보고를 중지한다. 상세 lease 계약은 [원본 Job 문서](platform-integration.md)를 따른다.
- n8n 목표 계약은 인증된 동기 요청, 업무 요청 ID·글 ID·본문 번호·필요 본문 입력, 최대 90초 이내 평문 요약 응답이다. 결과는 최대 500자로 검증한다. n8n에서 같은 요청 ID의 결과를 30일 재사용한다. 실제 워크플로의 지원 여부는 연동 시 검증한다.
- 플랫폼 Job은 최소 한 번 실행될 수 있다. job ID와 업무 대상/본문 번호를 함께 검사하며 수동 재접수로 새 job ID가 생겨도 같은 업무를 중복 반영하지 않는다.
- 결과 반영은 현재 점유·글 존재·본문 번호 일치·수동 요약 없음 조건으로 수행한다. 조건부 DB 갱신과 완료 기록을 같은 트랜잭션에 둔다. 점유 상실 후 외부 실행 취소는 보장하지 않으며 늦은 결과는 반영하지 않는다.
- DB 반영 후 완료 보고가 유실돼도 재실행은 완료 기록으로 중복을 막는다. 관련 화면·SEO 캐시 갱신은 재시도 가능하게 한다.
- 일시 실패는 최대 3회다. 입력 오류·외부 처리 결과 불명확은 무조건 재시도하지 않는다. 관리자에게 실패 상태와 재처리 동작을 제공한다. 실패가 글 저장·공개 실패로 이어지면 안 된다.
- AI 모델은 n8n 설정에 둔다. 특정 제공자를 끄적 코드에 고정하지 않는다. 전달/완료 기록의 정리는 [운영 기준](operations.md#observability)을 따른다.

### 외부 전달 문서

실제 API가 생기면 내부 개발 문서와 별도로 짧은 n8n 연동 가이드를 제공한다. 사용할 기능별 접근 가능한 문서·명세·예제 URL, 인증·지원 상태·필수 입력·오류를 안내한다. API 명세에는 요청/응답·문서 JSON·상태·분류·파일 처리와 실제 요청 예제를 둔다. 아직 없는 배포 URL·작동하는 예제를 만들어 적지 않는다.

## 공개 화면·검색·SEO·수익화

### 탐색과 표시

- 경로: `/`, `/posts/{slug}`, `/category/{slug}`, `/tag/{slug}`, `/search`, `/about`, `/privacy`. `/contact`는 필요가 생길 때 추가한다.
- 목록은 최신 공개일·ID 순이며 페이지당 12개, API 상한은 50개다. 대표 이미지·제목·요약·공개일·카테고리·태그를 표시한다. 무한 스크롤 전환 설정은 만들지 않는다.
- 상세는 제목·본문·대표 이미지·작성/수정일·분류·조회수·좋아요 수·이전/다음 글·관련 글·댓글을 제공한다. 조회수 기준은 [운영 문서](operations.md#observability)를 따른다.
- 이전/다음 글은 전체 공개 글의 최초 공개일·ID 순서에서 바로 앞뒤 글이다. 이전은 더 오래된 글, 다음은 더 최근 글이며 대상이 없으면 해당 링크를 생략한다. `/api/public/posts/{slug}/neighbors`로 조회하고 초안·비공개 글은 건너뛴다. 수정일로 순서를 바꾸지 않는다.
- 관련 글은 공개 글만 대상으로 현재 글을 제외한다. 같은 카테고리 3점·같은 태그당 2점, 동점은 최신 공개일·ID 순으로 최대 4개다. 0점은 제외하고 후보가 없으면 영역을 생략한다.
- 관련 글은 `/api/public/posts/{slug}/related`로 조회하며 공개본의 분류·태그를 기준으로 계산한다. 숨겨진 원본 글은 404이며, 상세 하단에 제목·카테고리·공개일을 서버 출력한다.
- 검색은 제목·본문 평문·요약·카테고리·태그를 대상으로 PostgreSQL 부분 문자열 검색과 `pg_trgm` 인덱스를 사용한다. 공백으로 나눈 검색어가 모두 일치해야 한다. 최대 100자, 제목 완전 일치 → 제목 부분 일치 → 기타 필드 일치 → 최신 공개일·ID 순이다.
- 짧은 검색어는 정확성을 우선하고 실행 계획·성능을 검증한다. 초성·오타 교정·추천은 후속이다.
- 밝은 배경·텍스트형 끄적 로고·단순 파비콘으로 시작한다. 모바일 반응형, 읽기 편한 본문 폭·행간·제목 계층, 코드·이미지·긴 글 가독성을 우선한다. 과도한 애니메이션을 사용하지 않는다.
- 블로그의 주제·성격·소개 문구를 임의로 정하지 않는다. 첫 화면은 소개 문구 없이 분류·검색·글 목록을 제공하고, 제목·빈 상태 등 기능상 필요한 안내만 사용한다.
- 사용자 요청으로 밝은/어두운/시스템 테마를 Lucide 해·달·모니터 아이콘 버튼으로 제공한다. 선택 상태·접근 가능한 이름·키보드 초점을 유지한다. 주요 로그인·댓글·활동·관리 동작은 같은 아이콘과 텍스트를 함께 사용한다. 선택은 브라우저에 보존하고 편집기·Viewer·안내 페이지에도 같은 색상 기준을 적용한다. 본문 폭은 PC에서 기존보다 넓게, 모바일에서는 가로 넘침 없이 표시한다.
- Semantic HTML, 이미지 alt, 키보드 이동·명확한 focus·충분한 대비·버튼/링크 구분을 적용한다. 이미지 지연 로딩·최적화, 정적 자원 캐시, 호출·쿼리 최소화와 Core Web Vitals를 고려한다.

### SEO와 RSS

- 1차는 공통 Viewer의 클라이언트 본문 표시를 사용한다. 제목·요약·metadata·구조화 데이터는 초기 HTML에 제공한다. 플랫폼 본문 SSR 미지원은 사용자 확인 사항이며 자체 Viewer로 대체하지 않는다.
- 글별 title·description·canonical, `og:title/description/image/url/type`을 제공한다. description은 [요약 정책](#automation)을 따른다. 중복 URL에서도 canonical은 하나의 정규 글 URL을 가리킨다.
- `/sitemap.xml`은 공개 글만 포함하고 `/robots.txt`를 제공한다. 초안·비공개 접근 제어를 robots 설정으로 대신하지 않는다.
- 사이트맵은 공개 글의 정규 주소·마지막 공개본 수정일과 홈·소개·개인정보·저작권 안내를 포함한다. `/api/public/sitemap`은 필요한 주소·수정일만 제공한다. Next의 동적 메타데이터 경로로 매 요청 생성하며 응답은 `max-age=0, must-revalidate`다. 단일 사이트맵 한도인 50,000개 주소에 도달하기 전에 분할해야 하며 초과 시 일부 주소를 조용히 누락하지 않고 오류로 알린다.
- 관리자·로그인·없는 글은 `noindex`, 검색 결과는 `noindex, follow`다. robots는 인증·관리 API와 로그인 처리 경로를 제외하고 사이트맵 주소를 제공한다. 관리자/로그인 화면은 크롤러가 `noindex`를 읽을 수 있게 별도 크롤링 차단으로 가리지 않는다. 목록 canonical은 유효한 분류·태그·검색·페이지를 보존하고 추적 매개변수는 제거한다.
- Article 또는 BlogPosting JSON-LD에 headline·description·image(해당 시)·datePublished·dateModified·author·mainEntityOfPage를 반영한다.
- `/rss.xml`은 RSS 2.0으로 최근 공개 글의 제목·URL·요약·공개일·카테고리·작성자를 제공한다. 공개·수정·비공개 전환 후 수동 작업 없이 갱신한다.
- RSS는 `/api/public/feed`의 최신 공개 글 50개를 사용한다. 전체 본문·편집본은 넣지 않고 요약을 평문으로 안전하게 인코딩한다. 최초 공개일과 정규 글 주소 기반 GUID를 유지하고 마지막 수정일을 피드 갱신일로 사용한다. 작성자는 사이트 정보의 공개 운영자명을 `dc:creator`로 표시하며 OIDC 계정명은 노출하지 않는다. 응답은 `no-store`이며 HTML의 구독 발견 링크와 하단 RSS 링크를 제공한다.
- 글별 Open Graph와 Twitter 카드에는 대표/기본 공유 이미지를 사용한다. 구조화 데이터 작성자도 같은 공개 운영자 표시를 사용한다. 외부 피드 리더가 이미 보관한 글 사본은 비공개 전환으로 회수할 수 없다.
- 전체 SEO 목표의 남은 조건은 플랫폼의 공식 본문 서버 출력 지원 후 연결한다. JavaScript 없이 본문·코드·이미지 대체 정보를 읽을 수 있고 같은 JSON의 서버/클라이언트 표현과 접근 권한·캐시가 일치해야 한다.
- 1차 완료를 본문 SSR 완료·검색 색인·검색 순위·AdSense 승인 보장으로 표시하지 않는다.

목록 보기 방식은 방문자가 페이지 또는 무한 스크롤 중 선택하며 브라우저에 저장한다. 초기값은 페이지 방식이고 기존 12개 단위 API를 재사용한다. 검색·카테고리·태그 조건은 추가 조회에도 유지한다. 무한 스크롤은 동시 요청을 막고 전환·이탈 시 취소하며, 실패하면 자동 재시도를 멈추고 수동 재시도를 제공한다. 페이지 방식으로 돌아가면 주소의 페이지를 다시 표시한다. 인피드 광고는 이어 붙인 목록에서도 최대 1개만 표시한다.

### 수익화와 기본 페이지


- 사용자 확정: AdSense·카카오 애드핏을 관리 화면에서 전환할 수 있는 광고 영역 구조, 소개·개인정보 페이지를 제공한다. 기본적으로 광고를 끄면 빈 공간도 숨긴다. 사용자 확정: 광고가 꺼졌을 때 자리만 표시하는 별도 설정을 제공하며 이 모드에서는 외부 광고 SDK·광고 요청을 생성하지 않는다.
- 사용자 확정 배치: PC(1280px 이상)는 글 하단과 우측 사이드 배너, 모바일·좁은 화면은 글 하단만. 긴 글은 PC에서만 본문 중간에 최대 2곳을 추가한다. 최소 3,000자·6개 상위 블록 간격, 뒤에 1,200자 이상이 남는 문단 끝을 사용하며 표·코드·목록·미디어 묶음을 나누거나 원본 JSON을 변경하지 않는다.
- 관리자 `/admin/settings`에서 실제 광고 사용·꺼졌을 때 자리 표시를 저장하며 재배포 없이 다음 열람에 반영한다. 저장값이 환경변수보다 우선하고 `환경변수 기본값 사용`으로 되돌릴 수 있다. 선택한 서비스의 발급값을 따로 보존한다. 실제 광고에는 유효한 서비스별 발급값이 필요하며 잘못된 실광고 설정을 자리 표시로 대체하지 않는다.
- 각 위치의 광고 슬롯을 따로 설정한다. 모바일에서는 중간·사이드 광고 요소를 생성하거나 요청하지 않는다. 관리자 편집/미리보기·소개·정책 페이지에는 광고를 넣지 않는다.
- 사용자 요청: 글 목록에 AdSense 인피드 광고를 지원한다. 홈·카테고리·태그·검색 목록에서 현재 페이지에 글이 4개 이상이면 세 번째 글 다음에 최대 1개 표시한다. PC·모바일 공통이며 광고는 글 개수·페이지 나눔·RSS에 포함하지 않는다. 별도 목록 광고 스위치(초기 꺼짐)와 전체 실광고/자리 표시 설정을 함께 따른다. 애드핏 선택 시 숨기되 입력값은 보존한다. 항상 광고임을 표시하고, 인피드 전용 슬롯·레이아웃 키를 사용한다. 가용 폭 250px 미만에서는 광고를 요청하지 않는다.
- 소개는 확인된 이용 안내만 제공한다. 공개 연락처와 운영자 표시는 [사이트 정보](../apps/web/src/lib/site-info.ts), 실제 개인정보 안내는 [개인정보 페이지](../apps/web/src/app/privacy/page.tsx), 콘텐츠 이용 조건은 [저작권 페이지](../apps/web/src/app/copyright/page.tsx)에서 관리한다. 제3자 자료에 일괄 라이선스를 부여하지 않는다.
- 독창적 실제 콘텐츠와 명확한 탐색을 전제로 하며 광고와 본문을 구분한다. 광고 클릭 유도 UI, 정책 위반 콘텐츠를 만들지 않고 모바일 읽기·검색·메뉴·댓글을 방해하지 않게 한다.
- 개인정보 페이지는 [운영 문서의 수집 항목](operations.md#observability)과 실제 외부 서비스 사용에 맞춰 작성한다. 외부 서비스 정책 확인·실계정 승인 상태는 운영 검증에서 별도로 다룬다.
- AdSense의 [개인정보 안내 요구](https://support.google.com/adsense/answer/1348695?hl=ko), [광고 배치 정책](https://support.google.com/adsense/answer/1346295?hl=ko), [인증 CMP 요구](https://support.google.com/adsense/answer/13554116?hl=ko)를 활성화 전에 확인한다. 안내 페이지를 추가했다는 이유로 승인이나 법적 검토 완료를 주장하지 않는다.

## 수용 조건

- 글·분류 CRUD, 상태 전환·자동 저장·미리보기·충돌 방지와 사용자/자동화 권한이 위 정책대로 동작한다.
- Editor JSON의 저장→조회→재편집→읽기가 일치하고 저장 실패·문서 교체·IME·모바일·Safari를 검증한다.
- 파일 중단/재개·응답 유실·키 교체·크기 초과·변환 실패·만료 URL·타인 파일 접근·미참조 정리를 검증한다.
- 공개 글 탐색·검색·SEO 요소·RSS가 상태 변경과 일치하고 비공개 내용이 API·HTML·캐시·첨부에 남지 않는지 확인한다.
- Job 중복·점유 상실·지연 응답·외부 장애·재시작에도 글은 저장되며 최신 본문·수동 요약이 보호된다.
- 본문 SSR 후속 검수는 플랫폼 지원 이후 별도로 완료 처리한다.
