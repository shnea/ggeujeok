끄적 · 운영 배포 안내

코드를 올리면,
검증 후 운영에 적용됩니다.

평소에는 변경 내용을 커밋하고 git push origin main을 실행합니다. GitHub Actions의 deploy가 성공하면 배포 완료입니다.

배포 흐름

개발 PCGit push커밋 전달
GitHub검증 · 빌드이미지 3개 생성
RegistrySHA로 보관기존 태그 보존
NASPull · 실행정상 응답 확인

NAS는 소스를 빌드하지 않습니다. 배포 전용 Runner가 내부 SSH로 기존 deploy 명령을 호출합니다. 개발 PC는 push 후 꺼도 됩니다.

필요한 명령

작업명령 · 위치
개발 실행개발 PC: ./scripts/dev.ps1
자동 배포개발 PC: git push origin main
직접 이미지 게시개발 PC: ./scripts/release.ps1
지정 이미지 적용NAS: sudo sh scripts/deploy.sh <SHA_12자리>

운영 주소는 https://shnea.kr, 개발 주소는 http://localhost:30145입니다.

운영 상태와 로그
sudo sh scripts/deploy.sh status
sudo sh scripts/deploy.sh logs
sudo cat .deploy/current
sudo tail -20 .deploy/history

환경값 확인·변경·암호화

개발 PC의 해당 프로젝트 폴더에서 PowerShell을 엽니다. .tools/dotenvx.exe와 그 프로젝트의 .env.keys가 필요합니다. 아래는 운영용이며, 개발은 .env.prod를 .env.dev로 바꿉니다.

내용만 볼 때

.\.tools\dotenvx.exe get -f .env.prod --format shell --no-armor --no-native
.\.tools\dotenvx.exe get REGISTRY_HOST -f .env.prod --no-armor --no-native

파일은 암호화된 상태로 유지됩니다. 화면에 보이는 실제 비밀값은 공유하지 마세요.

한두 값을 바꿀 때

.\.tools\dotenvx.exe set REGISTRY_HOST 'registry.shnea.kr' -f .env.prod --no-armor --no-native

set이 변경한 값을 자동 암호화합니다. 따로 복호화하거나 다시 암호화할 필요가 없습니다. 위 명령은 공개 설정 예시입니다. 비밀번호·토큰을 명령줄에 직접 쓰면 셸 이력에 남을 수 있습니다.

여러 값·비밀값을 편집기로 직접 수정하려면

파일 자체를 잠시 평문으로 바꿉니다. 아래 순서대로 한 단계씩 실행하고 실패하면 중단하세요. 다시 암호화할 때까지 커밋하지 마세요.

# 1. 복호화
.\.tools\dotenvx.exe decrypt -f .env.prod --no-armor --no-native

# 2. 값 수정 후 UTF-8로 저장하고 편집기 닫기
notepad .env.prod

# 3. 저장을 마친 뒤 재암호화
.\.tools\dotenvx.exe encrypt -f .env.prod --no-armor --no-native

# 4. 암호화 상태 검사
python scripts/check-ci.py

키·공개키 메타데이터는 바꾸지 마세요. 검사 실패 시 커밋을 멈추고, 편집기가 만든 평문 백업 파일도 올리지 마세요.

파일을 바꾸지 않고 env 형식으로 보거나 NAS에서 조회하려면

개발 PC에서 --stdout을 붙이면 화면에만 복호화합니다.

.\.tools\dotenvx.exe decrypt -f .env.prod --stdout --no-armor --no-native

NAS 운영 폴더에서는 다음 명령으로 조회합니다.

sudo ./.tools/dotenvx get -f .env.prod --format shell --no-armor --no-native

실제 서비스에 반영하려면

개발은 ./scripts/dev.ps1로 갱신합니다. 운영은 암호화 검사 후 변경을 커밋·푸시하고, 자동 배포가 연결된 프로젝트에서 deploy 성공을 확인합니다. 파일 수정만으로 실행 중인 컨테이너가 바뀌지는 않습니다.

.env.keys는 별도 보관하며 Git에 올리지 않습니다. 보통의 값 변경에는 키 교체가 필요 없습니다. NAS에서만 수정한 설정은 다음 배포로 덮어써질 수 있으므로 개발 PC의 Git 관리 파일에서 바꾸세요. 기존 DB 비밀번호는 환경파일뿐 아니라 DB 계정에도 맞춰야 합니다.

상세 절차: 환경파일 관리 설명

실패했을 때

단계확인할 것
verify / releaseGitHub Actions 로그에서 검사·빌드·이미지 게시 오류를 확인합니다. 기존 서비스는 유지됩니다.
deploy 연결Runner 상태와 SSH 연결을 확인합니다. 게시된 이미지는 보존하고 Re-run failed jobs로 deploy만 재시도합니다.
컨테이너 갱신운영 상태·로그를 확인합니다. 실패했다고 무조건 자동 롤백하지는 않습니다.
이전 이미지로 되돌리려면

이전 이미지와 현재 DB·설정이 호환되는지 확인한 뒤 같은 deploy.sh <이전_SHA>를 실행합니다. 현재·직전 버전은 .deploy/current·.deploy/previous에, 이전 설정은 .deploy/configs에 있습니다. 이미지를 바꿔도 DB나 파일이 복원되는 것은 아닙니다.

실제 DB·업로드 데이터는 기존 운영 환경에 지정한 위치를 계속 사용합니다. Registry 이미지 정리는 Registry 쪽 공통 예약 작업에서 관리합니다.

DB 복구 훈련·Registry 정리 프로그램은 이 프로젝트의 자동 배포에 포함하지 않습니다. 상세 명령과 기존 운영 정책은 운영 문서를 참고하세요.
